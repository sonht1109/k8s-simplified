Monitoring: Prometheus & Grafana

When something goes wrong in a cluster, you want to find out before your users do. Prometheus collects numbers (metrics) from the cluster, Grafana turns them into dashboards, and Alertmanager tells you when something is off.

Why monitor?

With one small cluster and one engineer, you might just look around by hand. Reality quickly gets bigger:

  • Several teams share a cluster, and one reports "my service was unreachable for a minute". How do you find out what happened?
  • Dev, staging and production each have a cluster, and the count keeps growing.
  • Questions like "do all Deployments have their expected replicas?" or "is the API server slow?" need data, not guesses.

A monitoring platform records numbers over time so you can look at history, spot trends and get alerted. Prometheus is the standard open-source choice for Kubernetes (it started at SoundCloud and is now a community project).

How Prometheus works

  • Metrics are numbers with a name and labels, such as CPU used or HTTP requests served, sampled over time.
  • Prometheus pulls (called "scraping") metrics at regular intervals from HTTP endpoints, usually /metrics.
  • It stores them in a time-series database: each value is saved with its timestamp, on local disk.
  • You query the data with PromQL, either in Prometheus' own web UI or via its HTTP API (so tools like curl or Grafana can use it).
  • Rules can raise alerts, which Prometheus sends to Alertmanager. That component groups them and notifies Slack, email or similar.

Where do the metrics come from?

  • The Kubernetes API server exposes metrics about itself and the cluster out of the box (see Lesson 2).
  • kube-state-metrics is a small add-on that turns object state into metrics: how many replicas does each Deployment want versus have, which Pods are pending, and so on. The API server alone does not give you that.
  • Exporters are helper programs that expose metrics for things that do not speak Prometheus themselves (for example node-exporter for machine CPU and memory).
  • Your own apps can expose a /metrics endpoint using a Prometheus client library. You then tell Prometheus to scrape it by adding a scrape target in its configuration.

Grafana: making metrics readable

PromQL results are raw numbers or JSON, which is hard for a manager (or you at 3 a.m.) to read. Grafana connects to Prometheus as a data source and draws charts, gauges and tables. It supports many other data sources too. Dashboards are built from PromQL queries, but you do not have to write them yourself: Grafana.com offers ready-made dashboards you can import by ID.

Hands-on: install both with Helm

You need any cluster (a local one such as minikube or kind works; see Lesson 26) and Helm. This lesson only uses Helm commands; how Helm works is explained in Lesson 27.

  1. Install Prometheus. Always run helm repo update first so you get a current chart version. 
    helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm repo update
helm install prometheus prometheus-community/prometheus
kubectl get pods
    The chart installs the Prometheus server, Alertmanager, kube-state-metrics and node exporters. Read the notes Helm prints at the end; they show how to reach the server.
  2. Check the Services. They are all type ClusterIP (internal only): 
    kubectl get svc
  3. Open the Prometheus UI. For a quick lab, expose it as a NodePort (Services); or just port-forward: 
    kubectl expose service prometheus-server --type=NodePort \
  --target-port=9090 --name=prometheus-server-ext
minikube service prometheus-server-ext      # or use node IP + NodePort

# alternative, works anywhere
kubectl port-forward svc/prometheus-server 9090:80
  4. Install Grafana and get its generated admin password: 
    helm repo add grafana https://grafana.github.io/helm-charts
helm repo update
helm install grafana grafana/grafana

kubectl get secret grafana -o jsonpath="{.data.admin-password}" | base64 --decode; echo
    The username is admin. (Yes, the password sits in a Secret; see Lesson 13.)
  5. Reach Grafana the same way: 
    kubectl port-forward svc/grafana 3000:80
  6. Add the data source. In Grafana go to Connections, Data sources, Add data source, Prometheus. For the URL use the in-cluster address http://prometheus-server (same namespace) and press Save & test.
  7. Import a dashboard. Go to Dashboards, New, Import, enter a dashboard ID from Grafana.com (the demo used 3662, a general Prometheus overview), pick your Prometheus data source and import. Hover over any panel to see the query behind it, which is a great way to learn PromQL.
Watch outExposing Prometheus and Grafana with NodePort is fine for a lab only. In real environments put them behind an Ingress with authentication.
TipMany teams install the whole stack with the kube-prometheus-stack chart, which uses an operator (CRDs plus a controller, see Lesson 12) to manage Prometheus, Alertmanager and Grafana together. Operators can also handle upgrades for you.

A taste of PromQL

# is each target up? (1 = yes, 0 = no)
up

# Deployments that don't have all their replicas
kube_deployment_status_replicas_available < kube_deployment_spec_replicas

# per-second HTTP request rate over 5 minutes
rate(http_requests_total[5m])

The first two work with the setup above; the third needs an app that exports http_requests_total.

Alerts

Dashboards need someone watching. An alert rule lets Prometheus watch for you: "if this expression stays true for N minutes, fire an alert". The for part avoids waking people up over a one-second spike. Alertmanager then sends the notification.

groups:
- name: example
  rules:
  - alert: HighMemory
    expr: container_memory_working_set_bytes > 500 * 1024 * 1024
    for: 5m
    labels:
      severity: warning
    annotations:
      summary: "Container is using more than 500 MB"
Try it: scrape and alert

Each press of Scrape adds a new sample (a random CPU %). The alert fires only if the last N samples are all above the threshold, just like for: in a rule.

Key takeaways

  • Prometheus scrapes metrics, stores them as time series and answers PromQL queries.
  • Metrics come from the API server, kube-state-metrics, exporters and your own apps' /metrics endpoints.
  • Alertmanager receives alerts from Prometheus and notifies Slack, email and others.
  • Grafana uses Prometheus as a data source; import ready-made dashboards by ID to start fast.
  • Helm makes installing the stack quick; use Ingress and authentication outside of labs.
